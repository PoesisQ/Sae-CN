# 性能实测

**当前 v0.3.0-preview.1：见 [0.3 Windows 构建实测](performance-0.3.md)。** 与已发行的
0.2 EXE 在同一主机顺序对照，分别测量普通程序内存/CPU 和独立 QA 首屏；新增 AZW3、
MOBI、FB2 样本。[0.2 轮次](performance-0.2.md) 包含先前优化、10 份 PDF 和四格式首屏。
以下保留 0.1 轮次的历史数据；各版本、不同样本与不同计时口径不可混为一个结果。

本轮解决用户实书长时间等待的问题，并测量新界面的代价。以下结果不代表 G5 全部通过。

## 环境与口径

Windows 11 26200 x64，i9-14900HX，24 核 / 32 逻辑处理器，16,774,565,888 字节物理内存，NVMe；详见 evidence/toolchain.json。实际窗口 DPI 150%，默认客户区 1180×840 逻辑像素。未清空系统缓存、未裁剪 working set、未隐藏图像、无常驻预热进程。未更改杀毒策略；杀毒扫描状态、卷与磁盘的对应关系尚未独立核对。

Release 构建，Slint Winit 软件渲染，MuPDF 1.27.2。字体/原生资源/页面缓存的预算分别为 32/32/24 MiB；这是可驱逐缓存上限，不是整个进程内存上限。UI 另外持有当前 RGB 显示副本，软件渲染器也有窗口缓冲；双页的可见像素及第二页字体会增加内存。

qa-windows.py 每次创建独立可见窗口和隔离配置，暖启动每种输入 20 次。首屏数据从程序入口计时，到分配真实页面和实际原生窗口 take_snapshot() 绘制完成；**不是操作系统合成器的外部可见时间戳，也不包含进程进入 main 前的加载时间**。完整进程创建至退出的墙钟时间另列于 JSON。冷启动未做，不把暖启动改称冷启动。

内存/CPU 由 profile-window.py 从进程外调用 Windows GetProcessMemoryInfo / GetProcessTimes 采样，普通发行程序不含 QA 计时器。每场 8 秒，取 3 秒后的稳态中位数，CPU 窗口约 4.8 秒。CPU 时间为 15.625ms 粒度；整机百分比按 32 个逻辑处理器归一化。结束后 profiler 仅终止其创建的子进程，因此这组采样不证明正常关闭；正常关闭、worker drop 和文件句柄释放另有测试。

原始数据与构建 SHA256：evidence/feedback/。只包含匿名编号和数值；不含用户书籍路径、正文、封面或配置。

## 找到的根因与修复

旧 font-kit DirectWrite select_by_postscript_name 会遍历所有系统字体并加载数据。真实 EPUB 的 STKaiti、MKai PRC 等字体名在当前机器上未必存在，反复 miss 导致全书排版放大这个成本。改为直接 family 匹配、惰性 family 名称索引和最多 256 项正/负结果缓存，不再逐个读取全系统字库。

同一 EPUB、540×540pt / 18pt 的原生全书分页：epub-02 由 **7403.99ms 降到 125.67ms**；epub-03 旧版在 30 秒被停止，修复后 **174.92ms**。这些是单次引擎剖析，不能与下面的窗口首屏混算。基线保留于 evidence/real-books-baseline.json、real-epub02-baseline.jsonl、real-epub03-baseline.jsonl。

epub-01 原先因不闭合的 HTML 空元素被严格 XML 检查拒绝。仅对内容 HTML 加入有大小、深度、节点和实体限制的兼容读取；OPF/container/NCX/外部 SVG 仍严格验证。原书字节不变，UI 显示修复提示。

后台先返回正确页面，再逐章补全总页数；目录只读标题/URI，不预先解析每个目标页。固定画布避免位图尺寸影响窗口布局，状态更新共享已有图像；首次命令行打开等初始 DPI/客户区通知稳定后再排版，避免先渲染临时小页面。

## 暖启动首屏

每项 20 个独立进程；p95 使用 nearest-rank。下面的「首屏绘制」包含真实文档像素，空白窗口单列。

| 输入 | 页面分配 median | 首屏绘制 median / p95 / max |
|---|---:|---:|
| 空白窗口 | 不适用 | 233.13 / 256.87 / 292.11ms |
| epub-01（403,878 B） | 217.37ms | 271.96 / 289.87 / 295.94ms |
| epub-02（573,193 B） | 256.66ms | 318.13 / 332.51 / 356.17ms |
| epub-03（471,781 B） | 250.79ms | 296.40 / 320.62 / 337.13ms |

80 次均正常退出、无报告错误。进程创建至退出的最大值为 epub-01 的 922.15ms，保留该离群值，未删样。三本实书首屏已脱离分钟级等待；≤300ms 挑战值并未在每本书上达到，更不能外推到所有 EPUB。

本地目录中的 10 份 PDF（2.75–31.52MB）全部完成原生首张光栅、文字结构、页数和目录探测，单次独立进程总时间 164.60–535.02ms。这是引擎探测，不是 10 份 PDF 的窗口首屏分位数；数据在 evidence/feedback/local-bench-pdf/。

## 发行程序稳态内存与 CPU

单位 MiB。Private Bytes 为提交的私有内存，Private WS 为驻留私有页，Total WS 含共享驻留页，三者不能混用。每行是一次 8 秒观察，不是多轮置信区间。

| 场景 | Private Bytes | Private WS | Total WS | 整机空闲 CPU |
|---|---:|---:|---:|---:|
| 旧版默认空白窗口 | 13.03 | 10.91 | 30.41 | 0.0505% |
| 新版默认空白窗口 | 13.88 | 11.71 | 32.10 | 0.0201% |
| epub-01 单页 | 55.88 | 53.43 | 76.09 | 0.0404% |
| epub-01 双页 | 61.80 | 59.29 | 82.52 | 0.0499% |
| epub-02 单页 | 73.01 | 70.48 | 115.16 | 0.0202% |
| epub-02 双页 | 78.92 | 76.37 | 121.03 | 0.0201% |
| epub-03 单页 | 72.63 | 70.00 | 104.34 | 0.0499% |
| epub-03 双页 | 84.05 | 81.32 | 115.71 | 0.0402% |
| 原创轻型 PDF 单页 | 22.88 | 20.66 | 42.86 | 0.0404% |

新版默认空白窗口多约 **0.85 MiB** 私有内存；这是各版默认窗口的整体观察，未隔离成单个控件成本。双页比单页多约 5.9–11.4 MiB，仍共用 24 MiB 页面缓存，不翻倍预算。以上样本的私有内存均在本轮目标内；不对大型图文 EPUB/扫描 PDF 作相同承诺。

## 稳定性与翻页

evidence/feedback/window-stress/fixture-00.json：可见原生窗口完成 500 次翻页（到书末后回到开头继续）、100 次字号调整、100 次窗口尺寸改变、30 次在两份 EPUB/PDF 样本间切换，共 730 项操作，错误 0。不是 500 页不同内容或 30 个不同书名的覆盖率声明。

页面缓存最大 **24,441,460 B（23.31 MiB）**；第 50/500 次操作 Private Bytes 64.19/64.85 MiB，增长约 0.66 MiB，随后字号/切书后回落。最终 45.43 MiB，句柄约 239–241，未见持续线性增长。短程测试不能替代长时间泄漏审计。

缓存命中 worker 翻页在此测试中可低于 1ms；完整可见延迟尚未逐次用系统合成器事件测量，故不把 worker 时间宣传为用户可见帧时间。Windows 实际滚轮输入已验证 1→2 页、双页 1–2→3–4 页，截图 evidence/ui-native-wheel-double.png。无生产环境固定帧率或空闲轮询定时器。

## SumatraPDF 对照

使用[官方稳定版下载](https://www.sumatrapdfreader.org/download-free-pdf-viewer)的 3.6.1 x64 便携版，签名 Valid，校验值在 evidence/sumatra-download.json。按[官方命令行参数](https://www.sumatrapdfreader.org/docs/Command-line-arguments)使用独立 -appdata、新窗口、单页/适合页面。未安装、未改文件关联，未将它纳入产品依赖或发行包。

同一主机、同一输入、相同进程采样方法：Private Bytes 空白 16.89、epub-01/02/03 为 30.66/77.02/54.47、轻型 PDF 15.40 MiB。Sae 在两本文本 EPUB 和 PDF 上仍较高；用户 CSS/CJK 字体负载、可见显示缓冲、缓存策略与各版默认窗口不同，应进一步用相同版面和字体分解对照。该组数据未标准化双方默认字体、窗口内容面积及元数据/更新行为，不能宣称 Sae 全面胜出；原始 CPU/WS 也完整保留。

Sumatra 的冷/热首屏、相同版面快速翻页对照和另一款 EPUB 视觉参照尚未完成。

evidence/feedback/icon-verification.json 与 icon-before-blank / icon-after-blank /
icon-after-double 的 summary.json。
