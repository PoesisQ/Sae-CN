# 0.4 实测与验收记录

2026-11-03；Windows x64，Rust + Slint 软件渲染 + 原生 MuPDF。

新增 PDF「多页」模式，按当前组实际页面尺寸选择两页或 2×2 四页；当单页缩小超过约 15% 或窗口过窄时使用两页或单页。保留独立单双页模式。混合比例逐组检查最多四个页面边界，不扫描全书。

显示的每页共享原有 RGB 缓冲、16 MiB 字节缓存；多页不预取下一组。不拼接整张大图，不新增依赖、常驻线程、定时器或全书索引。模型逐行更新，保留拖动中的交互状态。

侧栏展开时只创建一个文档区域的输入遮罩，首次点击只收起面板并恢复阅读焦点；窗口回归确认页码和请求代次均未变化。查找收起后保留已有搜索高亮。

## 普通发行程序性能

顺序运行，无编译并行；每组 2 次、每次 5 秒，取 3 秒之后私有内存中位数，再取两次中位数。使用外部 Win32 计数器，普通程序不带 QA 计时器。

| 场景 | 0.3 私有内存 MiB | 0.4 私有内存 MiB |
|---|---:|---:|
| 空白 | 13.69 | 13.68 |
| 竖向 PDF 双页 | 25.89 | 26.07 |
| 横向 PDF 双页 | 19.36 | 19.35 |
| EPUB 单页 | 26.84 | 26.90 |
| 横向 PDF 四页 | — | 19.44 |

各组末段约 1.8 秒采样内 CPU 时间增量均为 0 ms（受计时粒度限制，不代表数学意义的绝对零）。横向样本中，四页私有内存没有随页数翻倍，原因是减少了后台预取，且总光栅化面积受视区约束。

热启动至原生窗口快照就绪，每组 5 次；这不是 OS 可见首帧或冷启动验收：

- 0.3 双页：中位数 223.59 ms。
- 0.4 双页：中位数 203.04 ms。
- 0.4 四页：中位数 206.70 ms。

普通 EXE 24,109,568 字节，较 0.3 增加 104,960 字节（约 0.44%）。SHA256：`01d469a067aa54e0bc40d97930a52fe3338a36b6e1dea911742898a4041df500`。

上述数字属于所列自有样本与当前主机的热态测量，不能推导任意 PDF 或冷启动表现。

## 正确性验证

- 33 项原生测试通过（其中本地资源条件测试另启用 EPUB/PDF）；真实 Windows 窗口共 9 组、209 项操作，无错误。
- 实际读取 S:\书 的 5 本 EPUB、10 个 PDF，单双页、位置和三倍 PDF 可见区域缩放通过；Kindle 本地 HuffDic 条件样本本轮未提供，使用原有自有 Kindle 窗口回归。书籍没有复制到仓库或发行包。
- 横向、竖向、方形混合页面；四页顺序与尾组；第三/四页文字及链接、全文搜索高亮、缩放裁片、窄窗口回退；本机 150% 与 125/200% 受控缩放；缩窄再放大后对比四页未被工具条遮挡的图形像素位置，防止残留裁切。
- 目录、设置、搜索点击外部收起，不翻页、不发渲染请求；旧版导航、选择、搜索、沉浸工具栏和 EPUB/Kindle 显示回归通过。
