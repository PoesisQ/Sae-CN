# Sae Reader v0.6.2-preview.1

## 两张动态首页

直接启动程序时，Plasma 和 Blue Grain 每次交替出现。首页的左右方向键可切到下一张或上一张，第三张是原来的朱红透视版画。左下纸面的折线、标题位置和打开入口沿用原版，「Sae」的三个字母是镂空，里面的颗粒和右上图案取自同一片色场。[两种首页并排](evidence/iteration-0.6.2/covers.png) · [Plasma](evidence/iteration-0.6.2/plasma.png) · [Blue Grain](evidence/iteration-0.6.2/blue.png)

首屏先显示静帧。有焦点的首页以每秒 15 帧播放。失焦、最小化或打开选书框会暂停。连续 60 秒没有输入也会停住，再次操作时从暂停的位置继续。选择书籍后丢弃动画色场、图像和解码缓冲，双击文档直接走阅读路径。Windows 关闭「动画效果」时使用静帧。命令行可指定 `--cover=plasma`、`--cover=blue` 或 `--cover=print`，也可传 `--motion=static` 或 `--motion=30`。指定封面只影响本次启动。

## 两只拨轮

顶栏的平直边线从独立半圆轮缘的后方经过。按住向左时名称和刻线一同左移，当前挡位从固定指针下经过。一次整挡对应 88 个逻辑像素，约三分之二挡的行程才跨过挡点。过挡后松手切换布局，试拨后松手可退回原挡，抵住两端后反拖立即生效。普通鼠标滚轮两格换一挡。PDF 缩放盘展开直径由 86 调至 68 个逻辑像素，保留底板、倍率和三处可点按的预设。[按住时的连续实拍](evidence/iteration-0.6.2/view-drag.png) · [夜读半圆轮](evidence/iteration-0.6.2/view-wheel-dark.png) · [缩放盘](evidence/iteration-0.6.2/zoom.png)

旧实现把轮面位移经过整数挡位分支。慢拖时，视觉反馈丢了小数部分。这版将按住、回弹和静止位置都保留为浮点量，只在提交阅读布局时取挡位编号。通过 Windows 鼠标接口按住并依次移动 7、16、28、42、48 个逻辑像素，实际轮面位移为 0.07、0.15、0.29、0.48、0.56 挡。五个位置均取得变化的轮面像素，期间文档渲染请求计数保持不变。另回放了 14 次缩放手势，共 852 个采样点，覆盖四向直拖、四象限的顺逆圆周以及录制轨迹的正向和镜像。

## 原生绘制与开销

窗口沿用 Slint 的软件渲染后端。开发时在本机 RTX 4060 上运行了两份参考 GLSL。三个新进程单独建立 WGL 上下文耗时 137–177 ms，进程私有内存增加约 46.2 MiB。因此发行版在 Rust 中计算色场，以两块循环使用的 RGB 缓冲供现有窗口合成。Plasma 共用相邻色彩样本来计算五点模糊，Blue Grain 在 53 个颜色关键帧中只解码当前相邻的两帧，粒子纹理始终固定。前景缓冲的尺寸上限为 800 × 520。纸面大块区域直接填色，只有斜边的一小段需要光栅化。[Slint 后端与渲染器](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backends_and_renderers/)

在 640 × 360 下，以十个相同时间点对照原生 GPU 参考帧。用 0–255 的 RGB 值计算，Plasma 的逐像素均方根误差为 1.21–1.41，Blue Grain 为 0.96–1.13。五像素高斯低通后的区间分别是 0.56–0.61 和 0.81–0.91。比较对象是提供的两套 GLSL 输出。蓝白绿效果的原始视频没有纳入这组测量。

发行程序在 1770 × 1260 的实际窗口各采样三轮。CPU 按一个逻辑核心的占用率计，窗口处于前台时，Plasma 中位数为 13.86%，进程私有内存 16.52 MiB，Blue Grain 为 10.74% 和 16.37 MiB。静帧为 0.00% 和 13.65 MiB，备用版画为 0.00% 和 13.98 MiB。最小化后每轮观察约 2.5 秒，各轮读到的 CPU 占用最高 0.00%。EXE 为 24.68 MiB，较上一版增加 0.83 MiB。

普通发行版本也实际打开了 Windows 选书框，取消后恢复播放。前台静置超过一分钟后，CPU 采样为 0.00%（单核）。再次输入会唤醒动画。从选书框打开 PDF、停留在正文时，三秒采样的 CPU 占用为 0.52%，进程私有内存为 31.14 MiB。这项测量包含同一进程此前使用过 Windows 文件对话框的开销。

## Windows 阅读回归

Windows 11 x64 Build 26200，i9-14900HX，约 64 GiB 内存，NVMe，桌面缩放 150%。在同一台机器上，上一版与本版交替各启动 20 次，从程序入口计时到原生窗口取得首屏像素。测试驱动以 SW_SHOWNOACTIVATE 启动进程，首页首次取样为静帧。独立启动的三轮内存采样中，Windows 随后给了首页焦点，表内首页内存包含播放缓冲。内存来自普通发行程序，每种短样本三轮，每轮六秒，取后三秒的私有字节中位数。

| 样本 | 首屏中位数（旧 → 新） | 首屏 P95（旧 → 新） | 私有内存（旧 → 新） |
|---|---:|---:|---:|
| 直接启动首页 | 140.28 → 53.61 ms | 147.08 → 59.70 ms | 13.86 → 16.50 MiB |
| 30 页 PDF | 152.40 → 151.56 ms | 167.54 → 170.37 ms | 21.55 → 21.55 MiB |
| 复杂 EPUB | 153.21 → 152.37 ms | 169.95 → 163.73 ms | 18.83 → 18.89 MiB |

普通 PDF 和复杂 EPUB 各三轮稳态观察中，每轮末尾约三秒的进程 CPU 时间增量均为 0 ms。另用同一本 1156 页 PDF 各启动三次，内存各采样两轮、每轮 12 秒。双页首屏中位数 196.07 ms、私有内存 29.92 MiB，八页分别为 175.09 ms 和 25.44 MiB。上述结果为本机暖启动，重启系统后的冷启动、其他显卡及干净虚拟机仍待独立测量。

46 项 Rust 测试通过，另执行了 Markdown 公式基准与原生色场对照。文档回归实际打开本地 10 份 PDF、5 份 EPUB、1 份 AZW3，另检查三份曾因脚本引用而无法打开的 EPUB。窗口测试覆盖单双多页、键盘翻页、分页排版、搜索、全屏和 100% / 125% / 200% 显示缩放。源码与发行包只收录项目自有文档样例和匿名统计。[逐次实测数据](evidence/iteration-0.6.2/windows.json)
